# รายงานตรวจบัค Blockrealm Saga — 7 พฤศจิกายน 2026

ตรวจจากเว็บเกมต้นฉบับ build `3a9809765c4b0149` และทดสอบซ้ำหลังแก้เป็น `effb9648850b1bf9` โดยใช้พื้นที่เซฟทดสอบแยก ไม่แตะเซฟของผู้เล่นจริง

## บัคที่ยืนยันและแก้แล้ว

1. **SP/เงินติดลบเมื่อสกิลค้างรอออกท่า**: เกมตรวจทรัพยากรเมื่อสั่งสกิล แต่ไม่ตรวจซ้ำเมื่อเดินถึงเป้าหมาย ร่ายเสร็จ หรือออกจากคิว ระหว่างนั้นใช้สกิลอื่นได้ แก้ให้ตรวจ SP, Zeny, cooldown, เลเวลสกิล และสถานะตายทั้งก่อนเริ่มและก่อนออกท่าจริง ทดสอบสั่ง Bash จากระยะไกล → ใช้ Endure ระหว่างรอ → ถึงเป้าหมายด้วย SP ไม่พอ รวมทั้งสกิลคิดเงินและการใช้สกิลปกติ
2. **เสียยาฟื้น SP แม้ SP เต็ม**: แก้ให้ไอเทมฟื้น HP/SP ถูกใช้เมื่อมีค่าที่ไอเทมนั้นฟื้นได้ยังไม่เต็มเท่านั้น รองรับอาหารที่ฟื้นสองค่า และคงระบบคัมภีร์วาร์ป
3. **เกิดใหม่เชื่อมการอัปเดตอาวุธซ้ำ**: ยกเลิกการเชื่อม signal ซ้ำใน `_respawn` การเชื่อมเดิมจาก `_ready` ยังทำงาน ทดสอบตาย–เกิดใหม่ 3 รอบและอัปเดตค่า HP/SP/อาวุธ

## สิ่งที่ตรวจผ่าน

- โหลดสคริปต์ runtime 89 ไฟล์จากแพ็กจริง ไม่พบการคอมไพล์ล้มเหลว
- ชุดตรวจหลัก 7,583 assertions: อาชีพ 6 กลุ่ม × 2 สาย × 5 ขั้น × 3 แบบจัดสกิล, แต้มใช้ได้ครบ, เพดานเลเวล/สกิล, EXP, การเปลี่ยนอาชีพ, สูตรคราฟ 132 สูตร, วัตถุดิบมีแหล่งหา, ดรอปมอนสเตอร์, เควสหลักถึง 80 และเควสเสริม/รับรางวัลซ้ำ
- เซฟ 5 ช่อง: บันทึก/โหลด, JSON bundle, ติดตั้งในพื้นที่บัญชีทดสอบ, ตำแหน่งเซฟคลาดเคลื่อนได้เฉพาะความละเอียดเลขทศนิยมของ Vector3
- บริการบัญชีจริง 14 checks ด้วยบัญชี QA ใหม่สองบัญชี: สมัคร, ล็อกอิน, โหลดจาก session ที่สอง, แยกบัญชี, กัน revision เก่าทับใหม่, session หมดอายุ และออกจากระบบ ทุก session ที่สร้างถูก revoke แล้ว บัญชี QA และข้อมูลทดสอบยังอยู่แยกจากผู้เล่น
- หน้าเว็บบัญชี 20 checks: ตรวจรูปแบบข้อมูล, รหัสยืนยัน, จัดการความผิดพลาด, ล้างช่องรหัสผ่าน, ส่ง session ให้เกมครั้งเดียวและโหลดใหม่
- UI: หน้าต่างหลัก 11 หน้าบน PC 1280×720 และมือถือ 1055×488, 844×450, 488×1055 รวม 158 assertions ไม่มีหน้าต่างล้น viewport และไม่มีอินพุตเดินหลุดใต้หน้าต่างมือถือ
- สัมผัสจำลอง: ปัดขึ้น–ลงตรงระยะ, ไม่ไหลต่อเมื่อปล่อย, ล็อกแกน, รายการซ้อน/ส่งต่อเมื่อสุดขอบ, ไม่เผลอกดปุ่ม, แตะไอเทมทำงานหลังปล่อย
- ปุ่มไปหาแร่จากสูตรจริง: ออกจากโรงตีเหล็ก → เมือง → ทะเลทราย → เริ่มขุด → ได้ทองคำในกระเป๋า (เร่งความเร็วและปิด AI ศัตรูเฉพาะในชุดทดสอบเพื่อแยกการตรวจเส้นทาง; เปลี่ยนตารางดรอปหลังยืนยันชนิดแร่เพื่อให้ผลเก็บ deterministic)
- AUTO เก็บแร่ต่อเนื่อง, เปิดระหว่างขุด, รอเกิดแร่, ยกเลิกด้วยคำสั่งเดิน และออโต้ต่อสู้ปกติ
- ทุกพื้นที่ภายนอก/ดันเจี้ยนที่กำหนดไว้ 11 พื้นที่: ดันเจี้ยนไม่มีร้าน/โรงตีเหล็ก ร้านภาคสนามพ้นรัศมีมอนสเตอร์; ซากโบราณทะเลทราย/ป่าและประตูทางเดินไม่ถูกบล็อกในจุดที่ทดสอบ
- บอส Verdant Lv60/70 มีตัวละหนึ่ง, ตาย/เกิดใหม่/ตำแหน่ง/ท่าโจมตี และอาวุธระดับสูง 12 แบบ
- ดาเมจปกติ/คริติคอล/MISS, HP ตรงกับดาเมจ, ตั้งค่าซ่อนตัวเลข และลบตัวเลขเมื่อหมดอายุ ชุดทดสอบเก่ารอเพียง 1 วินาที แต่เกมปัจจุบันแสดง 1.15 วินาที จึงปรับชุดตรวจให้อิงเวลาจริง โดยไม่เปลี่ยนเอฟเฟกต์เกม
- ระบบเสียง 4 buses เชื่อมถึงลำโพง, ปลดเสียงหลังสัมผัสและฟื้นจาก interrupted context ด้วย browser API mocks
- ขนาดภาพมือถือ/แท็บเล็ต/หมุนจอ, เพดานจำนวนพิกเซล, particles, shadow และ MSAA
- ปาร์ตี้/แชท/แสดงผู้เล่น/เชิญ/เข้าร่วม/หัวหน้าลบสมาชิก ผ่านการจำลองเซิร์ฟเวอร์ในเครื่อง

## ประเด็นสำคัญที่ยังเปิดอยู่

**สูง — ระบบส่งของและแชร์ EXP ออนไลน์ยังเชื่อข้อมูลจากเครื่องผู้เล่น**

ใน `server/server.js` การรับ gift ตรวจเพียงรูปแบบ item/จำนวน/ปลายทาง ไม่มีการผูก session บัญชีและไม่มีการตัดคลังจากข้อมูลบนเซิร์ฟเวอร์ก่อนส่งต่อ การทดสอบเฉพาะในเครื่องยืนยันว่า client จำลองส่งของที่ไม่มีหลักฐานการเป็นเจ้าของให้ client จำลองอีกตัวได้ การแชร์ EXP ก็รับจำนวนจาก client และส่งต่อให้ปาร์ตี้ จึงยังเสี่ยงการเพิ่มของหรือ EXP ที่ไม่ได้มาจากการเล่นจริง

ไม่ได้ส่งข้อความทดสอบเหล่านี้ไปเซิร์ฟเวอร์ออนไลน์จริง และไม่ได้ปิดฟีเจอร์ส่งของ/แชร์ EXP ของผู้เล่นโดยพลการ ประเด็นนี้ต้องย้ายการยืนยันของ/การตัด–เพิ่มของแบบธุรกรรม และการยืนยันรางวัลไปยังฝั่งเซิร์ฟเวอร์พร้อมผูกบัญชี การแก้บัคสามจุดด้านบนไม่ได้แก้ประเด็นนี้ การตรวจครั้งนี้จึงไม่ใช่การรับรองว่าเกมปลอดบัคหรือพร้อมแข่งขันด้านเศรษฐกิจออนไลน์

## ข้อจำกัดของผลตรวจ

- สัมผัส เสียง และ fullscreen ส่วนหนึ่งทดสอบผ่านการจำลอง ไม่ได้วัดความร้อน แบตเตอรี่ GPU หรือทดสอบ Safari/Android บนโทรศัพท์จริง
- ยังไม่ใช่การเล่นต่อเนื่องหลายชั่วโมง หรือทดสอบทุกเส้นทางเดิน/ทุกการจัดสกิลและอุปกรณ์ที่เป็นไปได้
- ชุด headless มีข้อความเดิมจาก RendererDummy/Rect2i และการคืน resource เมื่อปิดการทดสอบ ซึ่งแยกจาก assertion failures และจากข้อผิดพลาด signal เกิดใหม่ที่แก้แล้ว ไม่ได้สรุปว่าข้อความเหล่านี้เป็น memory leak ระหว่างเล่นจริง
